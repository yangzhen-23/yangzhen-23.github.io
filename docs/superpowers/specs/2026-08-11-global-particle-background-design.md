# 全局交互粒子背景设计

## 目标

为个人主页的所有页面加入低对比度动态粒子连线背景。粒子缓慢漂移，鼠标靠近时产生柔和排斥，视觉语言参考中南大学人工智能学院首页，但颜色、密度和运动强度服从本站现有的深蓝—靛紫主题。

## 方案比较

1. **原生 Canvas（采用）**：自行实现粒子、连线和鼠标排斥。体积小、参数可控、无第三方运行时依赖，并能把物理计算拆成纯函数测试。
2. **直接引入 particles.js**：最接近参考站配置，但库版本老、会增加全局脚本，并且无障碍与页面生命周期需要额外补丁。
3. **纯 CSS 网格位移**：性能成本最低，但无法自然实现节点连线和鼠标避让，达不到用户明确要求。

## 视觉与交互

- Canvas 固定覆盖整个视口，在页头、正文和页脚之后渲染为背景层，不接管点击事件。
- 粒子使用低透明度蓝紫色圆点；距离较近的粒子用更淡的细线连接。
- 鼠标坐标由窗口级 `pointermove` 监听，进入排斥半径的粒子沿远离指针的方向移动，离开后继续自然漂移。
- 桌面端根据视口面积计算粒子数量并设置上限；窄屏减少密度和连线距离，避免遮挡与性能浪费。
- 页面原有背景渐变、卡片和文章排版保留，只把不透明背景调整为允许粒子隐约透出。
- 不实现点击生成粒子、粒子爆炸、颜色切换或配置面板，保持克制。

## 组件边界

- `src/lib/particle-field.ts`：纯 TypeScript 数学与状态更新函数，负责密度计算、边界循环和鼠标排斥。
- `src/components/ParticleBackground.astro`：创建 Canvas、管理尺寸与 DPR、运行绘制循环、监听窗口事件和清理资源。
- `src/layouts/BaseLayout.astro`：只负责在所有页面挂载全局背景组件。
- `src/styles/global.css`：规定背景层与站点内容层的层级，以及透明背景关系。

## 生命周期与容错

- Canvas 使用 `requestAnimationFrame`，页面不可见时暂停，恢复可见时继续。
- 窗口变化时重设 Canvas 像素尺寸并重建合理数量的粒子。
- `prefers-reduced-motion: reduce` 下不启动动画，只保留现有静态背景。
- 不支持 Canvas 或脚本执行失败时，网站仍显示原来的静态深色背景，导航和内容不受影响。

## 测试与验收

- 单元测试验证桌面/移动粒子数量、边界循环、远离指针不受力、进入半径后沿正确方向排斥。
- Astro 检查、完整测试、生产构建和构建产物检查必须全部通过。
- 桌面截图检查粒子不压过标题、卡片和文章正文；窄屏截图检查无横向溢出。
- 线上发布后检查首页、博客文章和项目页都能加载，并确认部署工作流成功。
